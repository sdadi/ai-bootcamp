1.1Finance words you'll meet in the labs

The labs read earnings calls and stock data. Ten words unlock almost all of it:

TickerA stock's short code. AAPL = Apple, NVDA = NVIDIA.
Earnings callA quarterly call where a company's leaders explain results to investors. The transcript is the text of that call.
RevenueAll the money from sales. Also called the "top line".
Net incomeProfit left after every cost, interest and tax. The "bottom line".
EPSEarnings Per Share = net income ÷ number of shares. "How much profit each share earned."
GuidanceManagement's own forecast: "we expect revenue to grow mid-single digits next quarter."
YoYYear-over-year: compared with the same quarter last year.
Fiscal quarterThe company's own accounting quarter. Apple's year ends in September, so its "Q3" is April–June.
SentimentIs this news good, bad or neutral for the stock?
Portfolio manager (PM)The person deciding what a fund buys and sells. Wants short, decision-ready summaries.
🧠 Analogy — the quarterly report-card meeting

An earnings call is a company's parent–teacher meeting. Revenue is all the fees the school collected, net income is what is left after paying every bill, EPS is that leftover split per family, and guidance is the teacher saying "here's what we expect next term". Investors listen for surprises.

1.2Picking the right model for a finance job

In a bank, model choice comes down to two questions:

  1. How much thinking does the task need? Non-reasoning models answer straight away — fast and cheap. Reasoning models think in hidden steps first — slower, pricier, more careful. Many APIs let you set a reasoning effort (none → high).
  2. How sensitive is the data? Closed models (GPT, Claude, Gemini) are the most capable, but your prompt travels to the provider. Open-weights models (Llama, Mistral, Gemma, GPT-OSS) can run on the bank's own servers, so client data never leaves — but you need GPUs and a team to run them.
🧠 Analogy — cashier vs auditor

A non-reasoning model is the bank cashier: counts notes fast, all day. A reasoning model is the auditor: slow, checks every step, costs more per hour. You don't send the auditor to count notes, and you don't let the cashier sign off the annual accounts.

1.4Lab 1A · Earnings-call summariser that returns JSON

The request: "Every quarter I read twenty earnings calls. Give me each one as the same fixed card — company, quarter, revenue, EPS, guidance, highlights, risks, outlook — so it can drop straight into our dashboard."

We'll send the same request to three models: GPT-4.1-mini (closed), Gemini 2.5 Flash (closed) and Llama 3.1 8B (open). The transcript is a made-up Apple call stored in a variable called transcript_apple_earnings_call.

Step 1 — Write the two prompts

Python · lab_1a_earnings_json.py · step 1
from openai import OpenAI
import json, os

client = OpenAI(api_key=os.environ["OPENAI_API_KEY"])

# WHO the model is + WHAT SHAPE the answer must have
system_prompt = """You are a finance analyst. Produce a concise, decision-useful summary of an
earnings call for portfolio managers. Return strict JSON with keys:
company, quarter, revenue, eps, guidance, highlights[], risks[], outlook."""

# The actual job + the data. The f"..." drops the transcript text into the {...} slot.
user_prompt = f"""Summarize the following earnings call transcript:
{transcript_apple_earnings_call}"""
  1. system_prompt is the job description: the role ("finance analyst"), the audience ("portfolio managers") and the output contract — the exact keys. highlights[] is a hint that this key should hold a list.
  2. user_prompt is the task for this one call. The f in front of the quotes makes it an f-string: whatever is inside { } gets replaced by that variable's value — here, the whole transcript.

Step 2 — Call the model and unpack the answer

Python · lab_1a_earnings_json.py · step 2
response = client.responses.create(
    model="gpt-4.1-mini",                                    # cheap + fast: fine for summarising
    input=[{"role": "system", "content": system_prompt},
           {"role": "user",   "content": user_prompt}],
    text={"format": {"type": "json_object"}},                # JSON mode: the reply must be valid JSON
)

raw_text = response.output[0].content[0].text                # dig the text out of the response box
summary  = json.loads(raw_text)                              # JSON text  →  Python dictionary
print(json.dumps(summary, indent=2))                         # dictionary →  pretty, indented text
  1. text={"format": {"type": "json_object"}} switches on JSON mode: the model must return valid JSON. Always mention "JSON" in your prompt when you use it — the API expects that.
  2. json.loads(raw_text) turns the JSON text into a Python dictionary, so you can write summary["eps"].
  3. json.dumps(summary, indent=2) goes the other way, only to print it nicely indented.

All three replies are valid JSON, yet the fund manager's dashboard runs summary["revenue"] > 90e9. It works for GPT and crashes for the other two, because their revenue is text. 1.5Prompting, finance style

You know the techniques; here is what they look like on a trading desk.

TechniqueFinance exampleUse when
Zero-shot"Classify the sentiment of this headline as positive, negative or neutral: Apple reports record-breaking revenue in Q4 despite market slowdown" → PositiveThe task is common and simple

Headline: Tesla stock falls after earnings miss expectations → Negative Headline: Amazon maintains steady growth amid economic slowdown → Neutral Headline: Apple reports record-breaking revenue in Q4 despite market slowdown → Positive Now classify: Nvidia shares surge after strong AI chip demand drives record quarterly revenue Sentiment: ▢

One example = one-shot, n examples = n-shot.

💰 Finance corner — net profit margin

Net profit margin = net income ÷ revenue. Out of every ₹100 of sales, how many rupees are profit? Profit going up is not enough — if sales went up even faster, the business is actually getting less efficient. The margin tells you which.

⚠️ Watch out — the 100-example problem

Few-shot is great with 3 examples. With 100 labelled headlines in every prompt, you pay for those tokens on every call, responses slow down, and you may exceed the context window. That is the moment to consider fine-tuning or retrieval instead.

1.6Fine-tuning in finance — why it's rarely the first move

A fine-tuning dataset is just many rows of "here is the input, here is the answer I want". For headline sentiment, one training row looks like this:

JSONL · one training example per line
{"messages": [{"role": "system", "content": "You are a senior financial analyst."}, {"role": "user", "content": "Quarterly operating profit rose to EUR 13.1 mn from EUR 8.7 mn a year earlier."}, {"role": "assistant", "content": "positive"}]}

Cheaper variants such as PEFT / LoRA train a small add-on instead of the whole model. Still, in finance fine-tuning hits four walls:

  1. Markets move weekly. New regulations, rates and earnings make a fine-tuned model stale within weeks — and you must retrain to update it.
  2. Client data is confidential. Uploading transaction records to a vendor's fine-tuning sandbox may break compliance rules.
  3. Decisions need live signals. Credit risk or portfolio rebalancing depends on today's prices and macro data — far too fast to retrain for.
  4. Most bank data is messy. PDFs, emails and memos must be hand-converted into clean input/answer pairs first.
What you needBest fit
A stable style or narrow task (e.g. label headlines our way)Fine-tuning (or a small specialised model)
Fresh facts — prices, news, today's numbersA tool that calls a data API
Answers from the bank's private documentsRAG over those documents
Several steps, decisions, checksAn agent (with tools + memory)

Step 1 — The tool: a normal Python function plus one decorator

Python · lab_1c_price.py · step 1 (pip install openai-agents yfinance)
from agents import Agent, Runner, function_tool
import yfinance as yf

@function_tool                                    # turns this function into a tool the LLM can call
def get_latest_stock_price(symbol: str) -> dict:
    """Fetch the current stock price for the given symbol."""   # the LLM reads this to decide when to use it
    ticker = yf.Ticker(symbol)                    # a handle for one stock, e.g. "NVDA"
    hist = ticker.history(period="1d")            # a table of the last trading day
    latest_close = hist["Close"].iloc[-1]         # column "Close", last row  → latest price
    latest_date = hist.index[-1]                  # label of that last row    → its date
    return {"price": float(latest_close), "date": str(latest_date.date())}
  1. @function_tool is like printing a menu card for your function. The SDK reads the name, the docstring (the description) and the type hint symbol: str (the input), and shows that card to the LLM.
  2. yf.Ticker(symbol) opens a handle to one stock. .history(period="1d") returns a pandas table (a DataFrame) for the last trading day — see the picture below.
  3. hist["Close"] picks the Close column; .iloc[-1] means "row at position −1", i.e. the last row.
  4. hist.index[-1] — the index is the row labels on the left (dates). The last label is the date of that price.
  5. float(...) and str(...date()) turn pandas types into plain Python values, so the result becomes clean text for the LLM.
💰 Finance corner — OHLCV

Every price table has the same five columns. Open: first trade of the day. High / Low: the day's extremes. Close: last trade — during market hours, the latest price so far. Volume: how many shares changed hands.

Step 2 — The agent, then run it

Python · lab_1c_price.py · step 2
stock_price_agent = Agent(
    name="Stock Price Agent",                                          # a label, shows up in logs
    instructions="Fetch Historical prices for a given stock symbol",   # its job description
    model="gpt-4.1",                                                   # the brain
    tools=[get_latest_stock_price],                                    # what it may call
)

output = Runner.run_sync(                                              # run_sync: no 'await' needed
    starting_agent=stock_price_agent,
    input="What is today's date, and what is the current stock price of Nvidia?",
)
print(output.final_output)
Today's date for the latest price data is August 15, 2025. The current stock price of Nvidia (NVDA) is $178.89.
💡 Why ask for the date too?

It's a lie detector. If the date matches today's trading day, the answer came from the tool. If it shows a 2024 date, the model answered from memory. Also notice: you typed "Nvidia", but the tool needs a ticker — the LLM filled in "NVDA" itself. Choosing tool arguments is part of the LLM's job.

2.1Finance crash course: the three ratio families

Labs 2A and 2F feed financial ratios to agents. If you can't read the ratios, you can't tell whether the agent's conclusion is sensible — so let's learn them first.

  • Valuation — "Is the price she's asking for a share of the café fair, compared with what it earns?"
  • Liquidity — "Can it pay this month's milk supplier and rent from the cash in the till and bank?"

⚠️ The lesson for agent builders

A ratio is a fraction — always look at the denominator. Same with liquidity: in our run the agent said Apple's current ratio below 1 signals "potential liquidity issues". A human analyst would add that Apple generates very large operating cash flow every quarter and keeps big long-term investments, so a ratio under 1 is a deliberate choice, not distress. Step 4 — Read the notepad back (the part that confuses everyone)

Before we write any code, look at what the session stores. User messages and assistant messages are stored in different shapes:

all_items = [ { "role": "user", "content": "Current Market Situation: ..." }, ← a plain string { "role": "assistant", "content": [ { "type": "output_text", "text": "### Current Portfolio..." } ] }, ← a LIST of parts { "role": "user", "content": "In this case, I'm reducing..." }, { "role": "assistant", "content": [ { "type": "output_text", "text": "..." } ] }, ]
🧠 Analogy — letter vs envelope

A user message is a single letter: read it directly. An assistant message is an envelope that can hold several pages (text, citations, …). To read it you open the envelope and take page 0's text: content[0]["text"].

Python · lab_2b_working_memory.py · step 4 (simplified, same result)
all_items = await session_ptf_rebal.get_items()    # everything on the notepad, oldest first
conversation_history = []                           # we'll fill this with (role, text) pairs

for i, msg in enumerate(all_items, 1):              # i counts 1, 2, 3 … (only for printing)
    role = msg.get("role", "unknown")               # "user" or "assistant"; tool-call items have no role
    content = msg.get("content", "")

    if role == "user":
        text = content                              # a letter: already a string
    elif role == "assistant":
        text = content[0]["text"]                   # an envelope: open it, take page 0's text
    else:
        continue                                    # skip tool calls and other item types

    print(f"{i}. {role}: {text}")
    print("--" * 50)
    conversation_history.append((role, text))       # save a clean (role, text) pair
  1. .get("role", "unknown") is a safe lookup: if an item has no "role" key (tool calls don't), you get "unknown" instead of a crash.
  2. enumerate(all_items, 1) gives you a counter i starting at 1 alongside each item — just for numbered printing.
  3. conversation_history ends up as a simple list of pairs: [("user", "Current Market…"), ("assistant", "### Current Portfolio…"), …]. This variable is the bridge into Lab 2C.
💰 Why this matters on a trading desk

Without the session, turn 2 ("reduce equity to 50%") arrives with no starting point — the agent can't know you came from 70/20/10, can't size the trades, and might invent a starting portfolio. For a bank, "the assistant forgot what the client said two minutes ago" is not a UX bug; it is a wrong trade.

2.4Lab 2C · Episodic memory: from today's chat to tomorrow's wisdom

In Lab 2B the notepad is binned when the session ends. Now we teach the agent to write a journal entry before the notepad is binned, file it in a cabinet that survives restarts, and read the most relevant entries the next time a client asks a similar question.

At 4 pm, before throwing away the notepad, a good trader writes one journal page: what the market was doing, what we changed, what worked, what didn't, lessons. Worked example — a plan-then-execute trend detector for Apple

The plan an LLM would write: (1) get the last 3 months of daily prices · (2) compute the 20-day moving average · (3) compare today's average with the one a week ago · (4) label it Uptrend or Downtrend.

🧠 Analogy — a batter's 20-innings average

One innings can be a fluke. A batter's average over the last 20 innings tells you their real form — and whether that average is rising or falling tells you the trend. A 20-day moving average does the same for a stock: the average of the last 20 closing prices, recalculated every day.

Self-consistency: let five analysts vote on an earnings surprise

💰 Finance corner — what is an "earnings surprise"?

Before results, analysts publish forecasts; their average EPS forecast is the consensus. If the company reports more, that's a beat. Here consensus was 1.20 and reported EPS was 1.25: a beat of (1.25 − 1.20) ÷ 1.20 ≈ 4.2%. But the market judges the whole picture — revenue growth, margins, guidance, management changes. An EPS beat with falling margins and a departing CEO can be a neutral surprise.

Self-consistency asks the model the same chain-of-thought question several times (with some randomness), then takes the majority vote. Each path focuses on different evidence:

Python · self_consistency.py · try it yourself
from collections import Counter
from openai import OpenAI

client = OpenAI()

cot_prompt = """You are a financial analysis agent.
Classify the earnings result as: Positive surprise, Neutral surprise or Negative surprise.
Reason step by step before producing the final classification.

Input:
EPS: 1.25 vs consensus 1.20
Revenue: +4% YoY
Margins: Declining
Guidance: Raised
Management: CEO departure announced

End with exactly one line: FINAL: Positive surprise | Neutral surprise | Negative surprise"""

answers = []
for _ in range(5):                                            # 5 independent reasoning paths
    r = client.responses.create(model="gpt-4.1-mini", input=cot_prompt, temperature=1.0)
    last_line = r.output_text.strip().splitlines()[-1]        # e.g. "FINAL: Positive surprise"
    answers.append(last_line.replace("FINAL:", "").strip())

votes = Counter(answers)                                      # counts each distinct answer
print(votes)                                                  # e.g. Counter({'Positive surprise': 3, 'Neutral surprise': 2})
print("Majority:", votes.most_common(1)[0][0])
  1. temperature=1.0 adds randomness, so the five paths reason differently. With temperature 0 you'd get five near-identical answers and the vote would be pointless.
  2. Asking for a fixed last line (FINAL: …) makes the answer easy to pull out with .splitlines()[-1].
  3. Counter tallies the answers; .most_common(1)[0][0] is "the top answer's text".

Cost note: five paths = five times the tokens. Use it for decisions that matter, not for every headline.

Step 4 — The loop (with comments on every line)

Python · lab_2e_news_loop.py · step 4
msg = input("User's request:")    # e.g. "Provide the latest 5 news in the Eurozone and specify the source for each one."
input_items: list[TResponseInputItem] = [{"content": msg, "role": "user"}]   # the searcher's running chat
latest_outline: str | None = None   # will hold the newest news summary
max_iteration = 4                   # retry limit
nbr_iterations = 0                  # retries so far

while True:
    # 1) The searcher writes (or rewrites) the summary, seeing the whole chat so far
    news_searcher_result = await Runner.run(web_news_searcher, input_items)
    input_items = news_searcher_result.to_input_list()                       # old chat + the new reply
    latest_outline = ItemHelpers.text_message_outputs(news_searcher_result.new_items)  # just the new text

    # 2) The evaluator grades ONLY the newest summary
    news_evaluator_result = await Runner.run(news_evaluator, latest_outline)
    result: EvaluationFeedback = news_evaluator_result.final_output         # the filled-in form

    # 3) Passed? Stop.
    if result.score == "successful":
        print("Links check is good ==> stopping the iteration.")
        break

    # 4) Failed: add the summary and the judge's feedback to the chat, then go round again
    input_items.append({"content": f"News Summary: {latest_outline}", "role": "system"})
    input_items.append({"content": f"Feedback: {result.feedback}\n for each item in the news summary, "
                                   "provide an external source link:", "role": "user"})
    nbr_iterations += 1
    if nbr_iterations > max_iteration:
        print("Reached max_iteration ==> stopping the iteration.")
        break

print(latest_outline)

💡 How many searches can actually happen?

The check is nbr_iterations > max_iteration, so with max_iteration = 4 the searcher can run 5 times: the first try plus 4 retries. Change it to >= if you want 4 runs in total. Either way, a limit is essential — a loop between two LLMs with no limit can burn money forever.

2.8Context and memory upkeep — the finance notes

You know context engineering. In a rebalancing step, a good context holds: the current allocation, recent volatility from the bank's database, relevant past decisions from long-term memory, and the description of a pricing tool — not ten years of trade history. Two framework behaviours worth knowing:

  • LlamaIndex can flush short-term memory into long-term memory when chat history crosses a token threshold (e.g. 40K tokens), into three blocks: static (fixed facts like the client's mandate), fact extraction (facts pulled out of the chat) and vector (similarity search over past turns).
  • CrewAI detects when the context overflows and either summarises it or stops with an error, depending on settings.

For long-term memory, two upkeep ideas: hierarchical summaries (detailed chats → daily summaries → an overall summary → a short client profile) and forgetting, where unused memories fade and recalled ones get stronger — modelled on the human forgetting curve.

💰 Compliance note on client profiles

Memory frameworks can build a "user portrait" automatically. In finance, keep it explicit and correctable — "max 35% per sector, set by the client on 12 Oct" — never an inferred guess about the client's mood or personality. Suitability rules require you to show where every client preference came from, and let the client change it.

Wrap-up

What to remember

  1. Pick models by data sensitivity first, reasoning depth second. Confidential data pushes you to self-hosted open models; deep analysis pushes you to reasoning models.
  2. Valid JSON isn't usable JSON. Name every key, type and unit — or use structured outputs.
  3. Tools make numbers trustworthy; interpretation is still the LLM's. Know your ratios well enough to challenge it (ROE 171%, current ratio 0.89).
  4. Working memory = the session notepad. Pass the same session every turn or the agent forgets the portfolio.
  5. Episodic memory = journal → cabinet → retrieve → paste into the prompt. Follow the variables: conversation_history → string → prompt → episodic_memory → Chroma → ['documents'][0][0].
  6. Checks need limits and contracts. A judge with a fixed form (output_type), a retry limit, and JSON contracts between agents make a system auditable.
